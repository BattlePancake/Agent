## Tasks

### T-1: Валидация полей формы авторизации
- **Jira Issue Key:** SCRUM-5

- **Summary:** Реализовать валидацию полей формы авторизации (Email/Password)
- **Description:** Обеспечить клиентскую/серверную валидацию формы авторизации: поля Email и Password обязательны, Email должен иметь корректный формат, Password должен соответствовать требованиям безопасности системы. Основание — функциональность «Авторизация пользователя».
- **Source Requirements:** R6, R7, R8
- **Acceptance Criteria:**
  - AC-1: Отправка формы с пустым полем Email отклоняется (R6).
  - AC-2: Отправка формы с пустым полем Password отклоняется (R6).
  - AC-3: Email некорректного формата отклоняется с сообщением об ошибке (R7).
  - AC-4: Пароль, не соответствующий требованиям безопасности системы, отклоняется (R8).
- **Dependencies:** нет
- **Priority:** Medium (обоснование: низкая критичность при отсутствии; политики формата/пароля уточняются OQ-3, OQ-6, MI-4)
- **Open Questions / Blockers:** OQ-3 (политика паролей), OQ-6 (тексты ошибок), MI-4 (определение корректного формата email) — требуют решения владельца требований до финализации текстов и правил.

### T-2: Проверка учетных данных и обработка ошибок аутентификации
- **Jira Issue Key:** SCRUM-6

- **Summary:** Реализовать проверку учетных данных при авторизации
- **Description:** Реализовать аутентификацию по email и паролю: успешная авторизация при совпадении учетных данных зарегистрированного пользователя; при неверном пароле — отображение сообщения об ошибке без авторизации; email незарегистрированного пользователя не допускается к авторизации. Основание — функциональность «Авторизация пользователя».
- **Source Requirements:** R1, R2, R3
- **Acceptance Criteria:**
  - AC-1: Пользователь с зарегистрированным email и корректным паролем успешно авторизуется (R1, R2).
  - AC-2: При вводе неверного пароля система отображает сообщение об ошибке и не выполняет авторизацию (R3).
  - AC-3: Email незарегистрированного пользователя не обеспечивает авторизацию (R2).
- **Dependencies:** T-1 (валидация формы предшествует проверке учетных данных)
- **Priority:** High (обоснование: ядро функциональности авторизации, RSK-4, AMB-4)
- **Open Questions / Blockers:** AMB-4 / OQ-4 (поведение и сообщение при незарегистрированном email), OQ-6 (тексты ошибок) — требуют внешнего решения.

### T-3: Блокировка учетной записи после неуспешных попыток
- **Jira Issue Key:** SCRUM-7

- **Summary:** Реализовать временную блокировку учетной записи после нескольких неуспешных попыток
- **Description:** Реализовать отслеживание последовательных неуспешных попыток авторизации и временную блокировку учетной записи после достижения порога. Заблокированный пользователь не должен иметь возможности авторизоваться. Основание — функциональность «Авторизация пользователя».
- **Source Requirements:** R4, R9
- **Acceptance Criteria:**
  - AC-1: После заданного числа последовательных неуспешных попыток учетная запись временно блокируется (R4; число пытает определения, см. OQ-1).
  - AC-2: Заблокированный пользователь не может авторизоваться, даже с корректными учетными данными (R9).
  - AC-3: По истечении срока блокировки поведение авторизации восстанавливается согласно решению по OQ-2.
- **Dependencies:** T-2 (блокировка основана на результатах проверки учетных данных)
- **Priority:** High (обоснование: риск DoS для легитимных пользователей и защита от перебора, RSK-1)
- **Open Questions / Blockers:** AMB-1/AMB-2, OQ-1 (порог попыток), OQ-2 (длительность и разблокировка), MI-1, MI-2 — критически важные параметры, требуют решения владельца требований до реализации.
